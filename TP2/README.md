### TP2 Details ###

Introduction
The goal of this team project phase is to add functionality to the TP1 requirements and build on the TP1 and HW2 experiences of the team to produce a TP2 submission.  Similar to Team Project Phase 1, this phase’s assignment requires a coherent team solution based on the various solutions each individual produced for the two Parts of the HW2 submission.

The First Part: The HW2 application enhanced the Foundations code by adding the GUI and supporting methods to create lessons learned and lists of lessons learned.  This is crucial for TP2, so the team must explore the various implementations and select one or parts of several that move the project forward.

The Second Part: Each HW2 folder contains a document that assesses a separate standalone LessonShare application, lists the functions it performs that would be valuable to the Team Project, and evaluates and lists the issues seen with the application before and may cause issues during integration into the Team Project submission.  AI is becoming a key part of all software.  Your team must know how AI works.  Each team member also needs to get familiar with the challenges of code that looks good from a user's perspective, but may not be designed and written with the idea that others will build on, leverage, and maintain the work.

The team is required to implement a class to provide persistent information and the CRUD (Create, Read, Update, and Delete) actions required to hold all the data for a lesson learned as required by the User Stories in the "Contributor" portion of the "Lessons Learned System - Initial User Stories" PDF document.  Locate this class in the "entityClasses" package.

In addition, the team must implement a list class to support the CRUD actions for lists of lessons learned.  One of these will be a persistent list of all the lessons learned in the system.  There will be subsets of all lessons learned, such as a list of lessons that contains a certain keyword or set of keywords for a search action.

Using these two classes, the team must implement all Phase Two User Stories by designing new GUI Windows that align with the "User Experience.pdf" the team produced for TP1.  To do this, the team builds on and enhances the Foundation solution as needed to create TP2 and TP3 to fully implement the letter and spirit of the provided user stories allocated to them.

Remember that the provided User Stories may be incomplete, may conflict with one another, and may be wrong. Your team must resolve these issues by engaging with the representative of the project’s stakeholders (e.g., your professors, TAs, and UGTAs) and produce a worthy submission well before the deadline.

Screencasts show that the deliverables' requirements have been satisfied and explain how.  Each team member must be a screencast presenter, and the length of each must be roughly the same.  It is desirable to have two team members collaborating to create each screencast.

The team must submit a set of PDFs using an outline to communicate the key points compactly.

The team must submit a ZIP archive of the TP2 folder, described in Task 1 below.  The detailed requirements for this team assignment are specified below.  Each team member must verify that the submission contents are correct and work as required before submitting the assignment, and verify that Canvas successfully received the submission before the deadline.
